# 任务一 · 技术路线对比分析报告

> 赛题：面向行业数据的智能实体挖掘与关系建模（赛题五）· 任务一 实体识别与自动化提取
> 命题单位：中国软件与技术服务股份有限公司
> 数据口径：40 篇人工核验公告（273 条标的物），同一评测器、同一评分公式
> 评分公式：**准确率 × 0.4 + 精确率 × 0.3 + 召回率 × 0.3**
> 说明：本报告全部数字为**实测值**，非估算；每条路线均在同一份金标上评测。

---

## 1. 结论摘要

| 路线 | 综合得分 | 精确率 | 召回率 | 相对规则基线 |
|---|---:|---:|---:|---:|
| ① 纯规则 / 关键词匹配 | 4.58% | 12.93% | 1.04% | — |
| ② 规则 + 表格列名机械解析 | 23.19% | 49.86% | 12.56% | +18.61 pp |
| ③ 大模型 + 提示工程（采购包汇总层） | 29.96% | 66.88% | 14.71% | +25.38 pp |
| ④ 提示工程修正粒度口径 | 79.98% | 94.07% | 75.92% | +75.40 pp |
| ⑤ 提示工程 + 包级收敛（当前最优） | **80.58%** | **92.24%** | **78.35%** | **+76.00 pp** |

**核心结论：**

1. 纯规则路线在本任务上不可用 —— 即便做了针对性表格解析，综合得分也只有 23.19%，
   因为「产品服务名称」「单价」「数量」大量以自然语言或附件形式出现，正则无法可靠定位。
2. 大模型路线的价值不在"能调用模型"，而在**提示词是否说清了评审口径**。
   同样是 DeepSeek + 相同输入，仅修正实体粒度与品目取值规则，
   综合得分从 29.96% 提升到 80.58%（**+50.62 pp**），是本项目最大单项收益。
3. 提升空间主要不在模型能力，而在**口径对齐**与**规范清洗**（详见第 5 节）。

## 2. 路线① / ②：规则法（对照组）

### 2.1 实现方式

| 版本 | 做法 |
|---|---|
| ① 纯字面匹配 | 正则抓取公告级「品目」「中标金额」，产品名用公告标题 |
| ② 表格列名机械解析 | 识别公告表格表头（`货物名称 / 货物品牌 / 货物型号 / 货物数量 / 货物单价`），按列取值；识别不到列名则该篇无输出 |

两者都不调用任何模型，不消耗 API 费用。

### 2.2 实测结果

| 字段 | ① 精确率 | ① 召回率 | ② 精确率 | ② 召回率 |
|---|---:|---:|---:|---:|
| 产品服务名称 | 2.50% | 0.37% | 21.95% | 6.67% |
| 品目 | 20.00% | 5.26% | — | — |
| 品牌（产品供应商） | — | — | 75.51% | 27.11% |
| 规格型号 | — | — | 79.76% | 33.17% |
| 单价 | — | — | 75.00% | 1.36% |
| 数量 | — | — | 59.26% | 8.21% |
| 总价 | 16.67% | 4.65% | 37.50% | 2.33% |
| **综合** | **4.58%** | | **23.19%** | |

### 2.3 失败原因分析（实测）

- **实体切分做不到**：规则法只能拿到"公告级"的一行，40 篇共抽出 104 条，
  而金标是 273 条标的物；行数与金标一致的只有 11/40 篇。
- **品牌 / 规格精确率可以（75%~80%），但召回很低**：只有表头结构规范的公告才能取到值，
  其余公告这些信息写在正文句子或附件里（例如「序号 1 | 供应商 | 项目（第1包）详见附件 | 详见附件 …」）。
- **单价几乎取不到**（召回 1.36%）：单价大量出现在附件报价表中，且常带"元/人/天"这类复合单位。
- **品目完全取不到**（版本② 为 0）：品目往往只在公告信息表里出现一次，
  而标的物是多行，规则法无法把公告级值正确分配到每一行。

> 结论：规则法适合做**辅助校验**（例如金额格式规范化、占位词清理），
> 不适合作为核心提取手段 —— 这与赛题"不建议仅用规则匹配完成核心提取"的要求一致。

## 3. 路线③~⑤：大模型 + 提示工程（本项目主路线）

### 3.1 技术组成

| 组件 | 选型 | 说明 |
|---|---|---|
| 大模型 | DeepSeek（`deepseek-chat`），可切 Qwen | 符合赛题"Qwen/DeepSeek 系列开源国产大模型"要求 |
| 生成参数 | temperature 0.1 / max_tokens 8192 / timeout 120s | 低温度保证输出稳定 |
| 上下文构造 | HTML 正文 + HTML 表格（± 附件文本与 OCR 结果） | 按运行模式决定是否纳入附件 |
| 附件解析 | python-docx / openpyxl / xlrd / python-pptx / pdfplumber / RapidOCR / legacy-doc | 按扩展名分派，`.doc` 按真实容器分流 |
| 容错 | 重试 3 次 + 递增退避；JSON 四级降级 | 第四级为括号配对抢救被截断响应 |
| 并发 | 2 线程（适配决赛 2 vCPU / 4 GB） | 每 10 篇原子写检查点，支持断点续跑 |
| 费用 | 按批次实际计费 | 40 篇单层全量约 5 分钟 |

### 3.2 提示工程迭代：每次改动的实测效果

| 迭代 | 改动内容 | 综合得分 | 变化 |
|---|---|---:|---:|
| 基线 | 采购包汇总提示词（强制"每个采购包只输出一条"） | 29.96% | — |
| 第 1 次 | 改为**跟随公告自身粒度**：正文逐条列出就逐条输出，只有明细全部指向附件才按包出一行 | **79.98%** | **+50.02 pp** |
| 第 2 次 | 增加"并列内容按标点逐项拆行" | 78.75% | −1.23 pp（**已回退**） |
| 第 3 次 | **包级收敛**：在确定性后处理中识别"公告只给采购包 + 明细全指向附件"，把附件展开出的多行收敛为包级行 | **80.58%** | **+0.60 pp**（相对第 1 次） |
| 第 4 次 | **品目双来源**：区分公告信息表的「品目」（公告级、所有行同值）与明细表的「品目号/品目名称」（行级、各行不同） | 已实现，待重跑量化 | — |

**关键发现（第 1 次迭代）**：原提示词写"每个采购包只输出一条"，
结果模型把 40 篇压成 86 条（金标 273 条），召回率暴跌到 14.71%。
改为跟随公告自身粒度后，实体数 244 条，召回率升到 75.92%，精确率同时升到 94.07%。

**第 2 次迭代为什么回退**：实测综合得分下降 1.23 pp。
按"不升则不保留"的准则回退，没有因为"看起来更合理"而保留。

## 4. 路线对比：为什么选择大模型 + 提示工程

| 对比维度 | 规则法 | 大模型 + 提示工程 | LoRA 轻量微调 |
|---|---|---|---|
| 综合得分（实测） | 4.58% ~ 23.19% | **80.58%** | 未实施（见 4.1） |
| 实体切分能力 | 无法按标的切分 | 跟随公告结构 | 取决于标注量 |
| 泛化到新公告格式 | 需逐个写规则 | 提示词即可覆盖 | 需重新标注训练 |
| 标注成本 | 无 | 无 | 需数百至数千条标注 |
| 硬件要求 | CPU | CPU（模型在服务端） | 微调需 GPU |
| 适配 2 vCPU / 4 GB | 是 | **是（本地只做解析与调度）** | 微调阶段不满足 |
| 单篇耗时 | 极快 | 秒级（含 OCR 时更长） | 推理更快，微调很慢 |
| 迭代速度 | 慢（规则叠加） | **快（改提示词即生效）** | 慢（需重训） |

### 4.1 关于 LoRA / 轻量微调的评估

**结论：本阶段不采用，但保留为后续可选路线。** 依据：

1. **决赛环境不满足微调**：官方提供 2 vCPU / 4 GB / 无 GPU 的轻量服务器，
   本地微调 7B 级模型不可行；微调必须在外部 GPU 环境完成后另行交付权重。
2. **当前瓶颈不是模型能力**：实测显示精确率已达 92.24%，
   主要损失来自「总价召回 14.73%」与「品目召回 60.53%」，
   而这两个问题的根因已定位为**金标口径与取值来源**，不是模型学不会。
3. **口径仍在变动**：40 篇金标目前只完成初审（复核与仲裁未完成），
   此时投入标注做微调，训练目标会随口径变化而失效。
4. **成本对比**：提示工程迭代一轮约 5 分钟 / 40 篇；微调需要标注 + GPU 训练 + 评测，
   在口径未定稿前性价比明显更低。

**若后续启动 LoRA，建议方案**：以 Qwen 7B 级基座，用 1038 篇公告中
已人工确认的样本构造指令微调集，4-bit QLoRA 单卡完成，交付权重 + 评测对比。

## 5. 当前主要失分点与改进方向（实测定位）

| 失分点 | 实测规模 | 根因 | 改进方向 |
|---|---|---|---|
| 总价召回仅 14.73% | 金标 129 行，仅命中 19 行 | 部分公告的标的级总价只存在于**附件**中，基础层只读 HTML 时无法取得 | 让基础层按需纳入附件文本；或对"明细指向附件"的公告启用附件级提取 |
| 品目召回 60.53% | 金标 152 行，命中 92 行 | 10 篇漏填中有 **9 篇的品目就写在 HTML 表格里**，属提示词未引导取值 | 已实现「公告级品目 + 行级品目名称」双来源规则，待重跑量化 |
| 规格型号精确率 77.73% | 预测 211 行 | 规格型号表述差异大，包含式匹配阈值偏严 | 调整匹配阈值或统一单位/符号写法 |
| 模型输出波动 | 单次得分区间 75.71%~87.94% | 同代码同提示词下，个别公告可能吐出 2 行或 69 行 | 正式成绩跑 3 次取中位数；对波动公告加确定性收敛规则 |

## 6. 复现方式

```powershell
# 规则法对照（不调用模型、不产生费用）
python _rule_baseline2.py

# 大模型路线：单层基础层 + 附件明细层
python main.py --input <数据集目录> --mode legacy --provider deepseek --workers 2

# 离线金标评测（不调用模型）
python run_evaluation.py <金标JSON路径> --predictions <结果JSON路径>
```

评测输出：汇总指标报告 + 逐字段错误明细（五类错误：值错 / 多填 / 漏填 / 多余实体 / 整条漏检）。
