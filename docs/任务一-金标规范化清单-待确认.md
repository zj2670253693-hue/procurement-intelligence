# 任务一 · 金标规范化清单（待复核仲裁确认）

> 生成时间：2026-10-04
> 用途：复核/仲裁阶段逐项拍板；拍板后由脚本一次性执行，避免人工逐条改 273 条。
> 重要：本清单只是**问题清单**，不含任何真实金标内容、公告 ID、密钥或审核人信息。

---

## 1. 为什么需要这份清单

初审稿里同一类「没有信息」的情况，出现了多种写法：

| 写法类型 | 出现在 | 数量 |
|---|---|---|
| `未公示`（精确值） | 初审导出 | 10 处 |
| `公告中品目未公示`（带说明的变体） | 初审导出 | 1 处 |
| `无品牌，制造商名称：XXX`（占位 + 真实信息混写） | 初审导出 | 2 处 |

这三种写法在评测里的后果完全不同，必须先统一，否则指标会失真：

| 写法 | 评测器当前行为 | 是否合理 |
|---|---|---|
| `未公示` | **直接拒绝金标文件**，拒绝评测 | ✅ 合理（强制先清洗） |
| `公告中品目未公示` | 被当成**正常类别值**参与统计 | ⚠️ 不合理，会把「无信息」算成有值 |
| `无品牌，制造商名称：XXX` | 被当成正常值，与模型输出逐字比对 | ⚠️ 需人工决定 |

---

## 2. 待拍板的三个问题

### 问题 1：`未公示` 到底算空值还是原文值

- **现状**：评测器会拒绝含该值的金标，必须先清洗
- **建议**：清成空字符串（数据库存空值，前端显示「未公示」）
- **需要确认**：复核人是否同意「空值 + 前端展示占位」这套口径

### 问题 2：`公告中品目未公示` 这类带说明的变体

- **现状**：会被当成真实类别参与评分
- **建议**：与 `未公示` 同等处理，清成空字符串
- **需要确认**：是否同意「凡是以占位说明代替字段值的，一律清空」
- **注意**：不能简单按「无」字开头匹配 —— 金标里 `无人机`、`无线麦克`
  是**真实产品名**，误清会直接造成漏报

### 问题 3：`无品牌，制造商名称：XXX` 这种混写

- **现状**：占位说明里夹带了真实信息（制造商名称）
- **建议**：保留 `XXX`（制造商名称），去掉 `无品牌，制造商名称：` 前缀
- **理由**：赛题字段是「品牌（产品供应商）」，制造商名称属于该字段的合法取值；
  逐字比对时前缀会让本可命中的值变成错误值
- **需要确认**：是否同意按此规则批量改写这 2 处

---

## 3. 执行方式

三项确认后，清洗由脚本一次完成，并留下审计记录：

```powershell
python clean_review_gold.py <初审或终稿JSON路径> --out <清洗后JSON路径>
```

脚本必须满足：

1. 只改写七个核心字段，不动审核依据、备注、状态、ID
2. 每处改写都记录（公告、条目、字段、原值、新值）
3. 输出差异清单供人工复核
4. 不覆盖输入文件
5. 清洗后的文件不得进入 Git

## 4. 技术侧已就位的保障

- 评测器对 `未公示` 的拒绝逻辑已实现并有测试覆盖（防止静默污染指标）
- 金标加载器已校验：40 篇不重复、`cases/items/data` 结构、七字段缺失按空串处理
- 本清单的三项规则确认后，只需扩展清洗脚本的规则表，评测代码无需改动

## 5. 另一项待确认的口径（与占位值无关）

**实体行数粒度**：

- 公告正文逐条列出标的物时 → **一条一行**（已有公告金标 56 行为此举证）
- 公告只给出采购包、明细全部指向附件时 → **一行一个采购包**（已有公告金标 2 行为此举证）
- 需要确认：复核人是否同意「行数完全跟随公告自身结构」这一口径

该口径已写入提示词并有回归测试锁定；如复核认为应改成「一律按采购包汇总」，
需要同步修改提示词、评测预期与前端展示，属于口径级变更，需在定稿前决定。
